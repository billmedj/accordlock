# AccordLock brand guide

## Canonical identity

- Product name: **AccordLock**
- Command and package prefix: `accordlock`
- Descriptor: **Execution integrity for AI and cloud automation**
- Tagline: **Everything agrees. Then it runs.**

Use `AccordLock` in prose. Use lowercase `accordlock` only where tooling
requires lowercase identifiers, such as command names, package names, image
names, labels, and URLs.

Do not write `Accord Lock`, `Accord-Lock`, `ACCORD LOCK`, or abbreviate the
product to `AL` in public material.

## Short description

AccordLock binds reviewed inputs, policy, authority, artifacts, and current
target state to one exact automation action before it runs. Live agent-plan
conformance remains an integration gate.

## Long description

AccordLock is an execution-integrity boundary for AI agents and cloud
automation. It evaluates authenticated evidence, issues a short-lived and
single-use authorization bound to one exact action and target state, consumes that
authorization transactionally, and fails closed when the evidence, authority, target,
or deadline changes.

## Claims discipline

Until the relevant roadmap gates close, describe AccordLock as a **technical
preview**, **reference implementation**, or **local evaluation candidate**.
Do not describe it as production-ready, certified, independently audited,
unbypassable, exactly-once, or formally verified end to end.

## Historical name

Earlier research used a different codename. That codename must not appear in
new product packages, commands, manifests, screenshots, or marketing copy.
Historical papers and immutable research deposits keep their original titles.
